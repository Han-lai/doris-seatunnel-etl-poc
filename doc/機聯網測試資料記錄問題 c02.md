# 機聯網測試資料記錄問題 c02

## WJ_02 測試紀錄問題
[Unicode Decoder](https://symbl.cc/en/tools/decoder/)

![](/uploads/upload_83c967ef2d6dd1a8c9294f0d69aea95a.png)


### 問題描述
在機聯網系統中的測試資料處理過程中，發現資料欄位中的 `PrimaryIdentifier` 字段包含多個非顯示字元（Unicode 碼為 `\u0000`）。這些字元導致了資料解析和顯示問題，進而影響到數據的準確性。以下是一個具體的測試資料範例：

| LineName | MessageName                 | UniqueID                            | TimeStamp                    | Source            | Target        | RequestID                           | MessageBody                                                                                                                                                                                                                                         |
|----------|-----------------------------|-------------------------------------|------------------------------|-------------------|---------------|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| wj_c02   | CFX.Production.WorkCompleted | 2b3d89fc-4ba3-4cf0-b3ea-77eada190433 | 2024-08-14 08:05:39.278 +0000 | PLC.B00.E022021207 | inline-control | f916caa8-d60c-4540-bd2f-411470455c70 | {"$type": "CFX.Production.WorkCompleted, CFX", "TransactionID": "8c5e2409-a2b4-41a2-b325-d30142136a32", "Result": "Completed", "PrimaryIdentifier": "C02-48\u0000\u0000\u0000\u0000B30721L0W24330577\u0000\u0000\u000056306066\u0000\u0000"} |

#### 具體問題：
在 `PrimaryIdentifier` 字段中，原本應顯示為 "C02-48B30721L0W24330577" 的資料卻夾雜了多個 `\u0000` 字元，這些無效字元導致資料處理和儲存的混亂，並且可能在不同系統之間進行資料交換時產生解析錯誤。

---

### 問題來源：Unicode Decoder 問題
[Unicode Decoder 工具](https://symbl.cc/en/tools/decoder/) 顯示，資料中存在大量的 `\u0000` 字元，這些字元本質上是無效的空字元，應該在資料儲存或傳輸過程中移除。

#### 錯誤範例：
```json
"PrimaryIdentifier": "C02-48\u0000\u0000\u0000\u0000B30721L0W24330577\u0000\u0000\u000056306066\u0000\u0000"
```
問題原因：這些 \u0000 字元在資料傳輸過程中被插入，可能是由於設備數據傳輸協議中的編碼錯誤，導致這些空字元未被過濾。


---
## 解決方案：使用 SQL 清理資料中的無效字元
為了解決這些無效的 Unicode 字元問題，我們採用了 SQL 查詢中的正則表達式和函數來清理 `PrimaryIdentifier` 字段中的無效字元。

### SQL 查詢範例：
以下的 SQL 查詢會將 MessageBody 字段中的 PrimaryIdentifier 提取出來，並使用正則表達式過濾掉所有非 ASCII 字元（包括 \u0000）：
```sql
SELECT
    MessageName,
    MessageBody,
    splitByChar('.', Source)[1] AS CommunicationType,  -- 切分並提取設備通訊種類 (PLC)
    splitByChar('.', Source)[2] AS Category,  -- 切分並提取大分類 (A00)
    splitByChar('.', Source)[3] AS SubCategory,  -- 切分並提取小分類 (E022044101),
    regexp_replace(
        JSONExtractString(MessageBody, 'PrimaryIdentifier'), 
        '[^\x20-\x7E]', 
        ''
    ) AS PrimaryIdentifier  -- 過濾所有非可見字符
FROM EAP.MessageBody_data
WHERE MessageName = 'CFX.Production.WorkCompleted'
  AND PrimaryIdentifier LIKE 'C02%'

```
說明：
* `JSONExtractString(MessageBody, 'PrimaryIdentifier')`: 提取 JSON 中的 `PrimaryIdentifier` 字段。
* `regexp_replace(..., '[^\x20-\x7E]', '')`: 使用正則表達式將所有非 ASCII 字元（範圍外的字符，包括 \u0000）替換為空字串。
* 查詢條件:
  ` PrimaryIdentifier LIKE 'C02%'` 用來篩選以 C02 開頭的資料。

## 後續步驟：
檢查其他類似的資料欄位，是否存在類似的無效字元問題。
對設備的數據傳輸協議進行驗證，確保不再出現這種無效字元的插入問題。
在資料輸入流程中，加入對無效字元的清理步驟，以確保資料的完整性和準確性。
