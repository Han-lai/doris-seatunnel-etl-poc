## 3.2.1 Doris 評估 

### 3.2.1.1 Doris 簡介 
![](/uploads/upload_7e87892f58439306f071beaaf10c5b54.png)

Apache Doris 是一個現代化的 **MPP（Massively Parallel Processing）分佈式分析數據庫**，專注於提供高速、簡單和高效的 **實時分析** 和 **即時查詢** 能力。Doris 支援海量數據的即時處理，適用於數據倉庫、實時數據分析等場景。
## **核心特性**
1. **高性能**
   - 使用列式存儲和向量化執行引擎，結合 MPP 架構，高效處理海量數據查詢。
   - 支持分區和分桶，提升查詢優化能力和性能。

2. **簡單易用**
   - 提供類似 MySQL 的語法接口，降低學習成本，開發者和數據分析師可快速上手。
   - 支持主流 ETL 工具和 BI 工具（如 Tableau、Power BI、Superset）的集成。

3. **即時分析**
   - 支援實時數據寫入，高頻小批量插入，適用於即時分析場景。
   - 支援多種數據源的批量導入（如 Kafka、HDFS、S3 等）。

4. **彈性和擴展性**
   - 支援動態節點擴展，輕鬆應對業務規模增長需求。
   - 提供線性擴展能力，節點增加時性能按比例提升。

## **技術架構**
Doris 的架構主要分為以下兩層：
1. **Frontend（FE）**
   - 負責查詢解析、優化、調度以及元數據管理。
2. **Backend（BE）**
   - 負責數據存儲和計算，執行查詢請求並完成高性能計算。
    
## **應用場景**
- **數據倉庫和 OLAP 場景**  
  適用於傳統數據倉庫構建與批量數據分析處理。
- **實時數據分析**  
  處理實時到達的數據流，快速響應即席查詢需求。
- **商業智能（BI）**  
  無縫對接 Tableau、Power BI、Superset 等 BI 工具，生成即時數據報表。

1.  測試內容

**動態分區 (PARTITION) 的屬性**

分區設計能夠根據時間條件有效地篩選數據，提升查詢效率，特別是針對範圍查詢。

- **自動建立分區範圍：** 
  範圍從 2024-09-01 至 2025-02-01，並隨著配置時間範圍變化，自動更新。

- **分區名稱：** 
  分區名稱會自動添加前綴 `p`，例如 `p202409`。

 **分區設計 (PARTITION BY RANGE)**

表格使用 `TimeStamp` 作為分區鍵，並依日期範圍進行分區。以下為範例範圍設定：

- **p202409** 覆蓋範圍：2024-09-01 至 2024-10-01
- **p202410** 覆蓋範圍：2024-10-01 至 2024-11-01

 **自動分桶 (BUCKET AUTO) 的屬性**

```sql
-- 自動分桶設定 (DISTRIBUTED BY HASH)
DISTRIBUTED BY HASH(`TimeStamp`) BUCKETS AUTO

```

自動分桶機制能減少不必要的資源浪費，並平衡讀寫性能。
使用 `DISTRIBUTED BY HASH` 並以 `TimeStamp` 鍵作為分布鍵，並啟用了 `BUCKETS AUTO` 功能。自動分桶根據系統內部配置（如分區大小和數據量）動態調整分桶數量。具體結果如下：
    - **分區 p202409** 使用了 10 個桶。
    - **分區 p202501** 則只有 2 個桶，說明該分區數據量較少，因此分配了較少的分桶數。

- **動態分區**：自動根據配置創建和刪除分區，無需手動干預。
- 動態分區相關設定 (Dynamic Partition)
```
PROPERTIES (
    "dynamic_partition.enable" = "true",
    "dynamic_partition.time_unit" = "MONTH",
    "dynamic_partition.start" = "-2",
    "dynamic_partition.end" = "2",
    "dynamic_partition.prefix" = "p",
    "dynamic_partition.buckets" = "10",
    "dynamic_partition.storage_policy" = "",
    "dynamic_partition.start_day_of_month" = "1"
)
```

| **錯誤類型**                     | **問題描述**                                                                                   | **錯誤代碼**           | **錯誤描述**                                                                                              | **處理建議**                                                                                              |
|---------------------------------|------------------------------------------------------------------------------------------------|------------------------|---------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| **資料過長錯誤** (MessageBody 長度過長)   | 資料行中的 `MessageBody` 超過了 Doris 設定的最大長度限制。                                            | `Doris-01`             | `ERROR_DESCRIPTION: The length of input string exceeds the schema length. First 32 bytes: [{"$type":"CFX.Production.UnitsAr]` | - 檢查資料大小，確保每條資料行的長度符合 Doris 的最大限制。<br> - 調整資料結構或將過長的資料拆分為多個小部分。 |
| **資料質量錯誤** (DATA_QUALITY_ERROR)     | 加載過程中，資料過多被過濾掉，導致資料無法正確加載。                                             | `DATA_QUALITY_ERROR`   | `ERROR_DESCRIPTION: Too many filtered rows, data quality issue.`                                           | - 檢查並清理資料源中的不符合要求的資料。<br> - 可以調整過濾條件或修正資料問題後再進行加載。               |
